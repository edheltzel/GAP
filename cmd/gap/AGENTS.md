# AGENTS.md

## Purpose

`gap` publishes this checkout's `global/AGENTS.md` and each `global/commands/*.md`, and installs each component pinned in `gap.toml` from `gap.lock`.

## Ownership

- `cmd/gap/` owns publish, install, skill adoption, drift, and the utility lifecycle (`gap add`, `update`, `remove`, `list` in `utility.go`).
- Policy text stays in `global/`. Skill source stays in component repos. Pin locations: [Components](../../README.md#components), [Add a utility](../../README.md#add-a-utility).

## Local Contracts

Installation, source checkout selection, and update requirements: [Install `gap`](../../README.md#install-gap).

`gap sync` publishes unless the effective profile is `crew`; see [project setup](../../README.md#project-setup). `gap sync --remove-codex-legacy` is valid only for machine publication. Component status and its failure conditions are described in [components](../../README.md#components). `gap restore [id]` reinstalls selected drifted component skills from the lock. Pin commands and their locks: [Commands](../../README.md#commands). `gap -h`, `gap --help`, and `gap help` print styled usage and exit 0. Invoking `gap` without a subcommand prints help and exits 2. An unknown command or extra arguments exit 1. A skipped destination or a failed skills step exits 1. Drift kept with both destinations complete exits 0. Skip, an incomplete keep, or drift with no terminal exits 1.

The setup breadcrumb contract, including the crew exception, and the Echo adapter ledger are in [Project setup and doctor](#project-setup-and-doctor).

### Sync steps

1. Resolve `$HOME` and `CODEX_HOME`. Empty `CODEX_HOME` means unset. A relative `CODEX_HOME` is refused.
2. Merge gate. Apply the [merge and publish limits](../../README.md#step-2-merge-the-change). Unset `origin/HEAD` is a refuse.
3. Selection. Groups, flags, and terminal output are described in [Choose what syncs](../../README.md#choose-what-syncs). An unknown id is refused before any write and names the valid ids. The line prompts default to all or yes on empty input, ask again for an invalid group answer, and read one shared stdin reader so a pasted burst keeps every answer. In those line prompts, quit, end of input, or choosing nothing prints `Nothing synced.`, writes nothing, and exits 0. A skipped component is not fetched and its installer does not run. A skipped group is not a failure and lasts for this run. `--remove-codex-legacy` with `policy` skipped is refused. The crew profile returns before selection.
4. Publish `global/AGENTS.md`. Rewrite `](docs/agents/` links to the absolute `global/docs/agents/` path in this checkout. The payload sits between `<!-- gap:begin -->` and `<!-- gap:end -->`. The Cursor file gets an `alwaysApply: true` frontmatter wrap before those markers only when GAP creates it or migrates an older whole-file publish. Write regular files only. A symlink is foreign. Then publish each top-level `global/commands/*.md` unchanged, as a whole file, to each command folder in the `harnesses` table (`harness.go`): `~/.claude/commands/`, `~/.pi/agent/prompts/`, and `~/.omp/agent/commands/`. Commands are not spliced. A missing `global/commands/` publishes nothing.
5. Ledger each written destination in `~/.gap/published.json`. A policy entry is the sha256 of the block between the markers, not the whole file. A missing policy file is written as markers plus payload. A file with complete GAP marker pairs on standalone lines is updated by replacing only the last pair and its contents. Everything outside that pair stays byte for byte. When the on-disk file already equals the publish, the destination is left in place and no recovery copy is made. Otherwise the previous file or symlink is moved under `~/.gap/recovery/<dest-id>/<timestamp>/` before the new file is installed (`<dest-id>` is the destination path relative to `$HOME`). If that rename cannot cross filesystems, the previous file is copied with its mode, fsync'd, verified, then the live destination is re-checked and only then removed. A destination that changes or disappears during that copy is refused, not aborted. Older copies for that destination are then pruned, keeping the 3 newest regular files. A displaced user symlink is never pruned. A moved leftover `.<filename>.gap-recovery-*` folder is never pruned. A prune failure prints a warning and does not fail the sync. Recovery stays out of harness rule directories. Leftover `.<filename>.gap-recovery-*` directories next to a managed destination, left by an earlier build, are moved into `~/.gap/recovery/<dest-id>/` and the new path is printed. A failed move prints a warning and leaves the folder in place. A concurrent edit that lands only in the recovery copy prints a warning with that path; a retained previous file prints its recovery path. A refused concurrent change names the recovery path, and a failed restore is included in that refusal. A file whose whole contents match the ledger digest, or equal the current unmarked payload, is an older whole-file publish. It is rewritten as markers plus the current payload. Anything else is foreign. A terminal asks once to append the GAP block. Yes copies the file to `~/.gap/backups/` and appends the block. The rest stays, so the harness keeps loading it. No, or no terminal, leaves that file alone. Other destinations still publish. A symlink cannot be spliced. Yes moves it into `~/.gap/recovery/` and writes a regular file. If that replace stops before the move, the empty recovery folder is removed. That harness stops loading the old target. The recovery copy keeps the bytes only. A command entry is the sha256 of the whole file. A foreign command file is replaced after a yes. The backup keeps the bytes only.
6. If this run wrote the Codex policy file, add SessionStart and SubagentStart hooks that `cat` it. The file counts as this publish when its GAP block equals the payload. `--remove-codex-legacy` runs before that hook install. It strips an old policy prefix from `CODEX_HOME/AGENTS.md` only when this run published the policy file and both hooks were already in `hooks.json`. The cleaned ledger value is `cleaned`, not a digest.
7. The effective `gap.toml` and `gap.lock` were resolved before publication. A missing `gap.toml` is an empty distro. Schema must be `"2"`. `~/.config/gap/gap.toml` may add a component (a table with `repo` whose id the distro does not use); its pin comes from `~/.config/gap/gap.lock`, and a missing pin names `gap update <id>`. A project or profile file that adds one, or a user table with `repo` on a distro id, is refused. Every selected component needs a lock entry or sync stops before publication. Sync never moves pins. After selection and before publication, each pin is fetched into `~/.gap/store/<id>/<commit>` (reused, with no network, when its on-disk source tree matches the lock). The store keeps git's file modes, so installed copies stay writable and executable bits survive. It is trusted only after its worktree tree id matches the lock, checked on every use with a temporary Git index and object directory. Seed that index from `HEAD`, then stage changes without forcing ignored files. This ignores untracked build output while still detecting tracked edits, deletions, and mode changes. The store's real index and objects stay untouched. `.git` stays so the tree can be checked again. A mismatched tree is an error and is not installed. When the verified store has a `gap-utility.toml` (`manifest.go`), it supplies the [installation declarations](../../README.md#publish-a-utility); `names` narrows its skills, and `install` or `doctor` in the spec beside a manifest is an error. A distro store without one keeps the spec's `names`, `install`, and `doctor`; user utilities require a manifest. A component repo is `github.com/owner/repo` (clone URL `https://github.com/owner/repo.git`), a `file://` URL, or an absolute path.
8. Install selected skills as defined in [Manage skills](../../README.md#manage-skills), including load levels, destinations, component-owned installers, and runtime requirements. A component's install hook (its update hook after a first install) runs only when `installed` in `~/.gap/state.json` differs from the pinned commit. Successful hooks are recorded before the next component starts; a successful declarative install also enables later update hooks. A user component's hook first passes `trust.go`: a `[trust]` match runs; otherwise a terminal asks `[y/N]` for that execution and no terminal skips the hook and exits 1. Distro components are trusted. Each manifest `commands` file publishes like `global/commands`, skipping a destination that already holds the same bytes under its ledger digest; command ownership is checked against all registrations and outstanding copies before any publication. Each placed copy adds its ownership to `state.json`, retaining earlier home skill names and command paths until removal; removal follows [Add a utility](../../README.md#add-a-utility). User utility skills cannot use project load. Add and update verify both skill destinations exist and match the source hash. That hash skips `node_modules`, `.git`, `__pycache__`, `__pypackages__`, and `metadata.json` on both the source and the installed copy.
9. Adopt existing skills.sh installations as described in [Manage skills](../../README.md#manage-skills). A missing skills.sh lock is no takeover. A lock that exists but cannot be read or parsed fails that skill's migration: the installed copies and the lock stay as they are, the error names the lock path, and sync or utility install exits 1.
10. Drift check. Compare each managed skill with its pinned store and apply the [drift choices](../../README.md#manage-skills). After drift resolution, including failed repairs, each `~/.empryo/skills/<name>` whose content hash differs from the resulting `~/.agents/skills/<name>` prints one warning; Empryo loads that copy first. The name `empryo` is Empryo's own and is skipped. Each `$JCODE_HOME/skills/<name>` (`~/.jcode/skills` when unset) that differs prints one warning naming both paths too. gap never writes or deletes in either folder, and the warnings do not change the exit code.
11. Empryo pins. When `~/.empryo/config.json` exists and its `skills.autoLoad` differs from `empryoPins` (`do-todo`, `do-commit`, `but-axi`), print the `settings` call that sets it. gap only reads that file. Empryo's `settings` tool cannot write `presets`, and a global `skills.autoLoad` beats any preset, so GAP ships no preset.

### MCP servers

`mcp.go` implements the [MCP manifest and lifecycle contract](../../README.md#publish-a-utility) through the `mcp` field of `harnesses`. `stateEntry.MCP` maps `<harness>:<name>` to a `mcpRegistration` containing the expanded server's digest and absolute configuration target. Presence checks read `mcpServers` from `.claude.json` or `mcp.json` under that target, or run `codex mcp list --json` with that target as `CODEX_HOME`. One run lists Codex servers once per target with `codex mcp list --json` and keeps that inventory current after each add and remove, because each list call also checks every configured server's auth. `gap remove` records a finished uninstall hook (clears `Installed`) before MCP cleanup, so a retry after an MCP failure does not run the hook again.

### Project setup and doctor

Run `gap init --adopt [dir]` for an existing project, or `gap init [dir]` for a new one; `dir` defaults to the current directory. Both create `.gap/gap.toml` only when absent, using `profile = "project"` and the directory name as the slug. Existing configuration must parse and contain a non-empty string `slug`; init reports an error before project writes otherwise. Init appends a short policy pointer to an unmarked `AGENTS.md`, preserving its existing text. With `--adopt`, an existing `AGENTS.md` stays byte-identical, including an empty file. A missing `AGENTS.md` is created in either mode, and a file containing either GAP marker stays unchanged. Non-regular `AGENTS.md` files are refused. `--adopt` also lists existing agent, Forge, task, and stack files. Successful project setup checks Recall through its CLI and adds `gap provisioned <slug>` using the persisted slug, unless a matching breadcrumb already exists anywhere in that project's history. Project-file provisioning failures add no breadcrumb; keeping an adopted or marked file still reaches the Recall check. Missing Recall prints a notice and succeeds. A failed Recall search or add reports an error and makes init exit `1`; project files already written stay in place for a retry. GAP never writes Recall's database directly. Crew setup, including a later init on a project with persisted `profile = "crew"`, never calls Recall. Init does not run the Forge interview.

Doctor also asks Echo's verified pinned store for `scripts/install.sh --list-installed`. A successful report replaces Echo's adapter list and store commit in `~/.gap/state.json`, preserving other component entries. The current Echo pin lacks this optional flag: doctor prints `echo reported nothing; no adapters recorded` and leaves the ledger unchanged. This skipped report does not itself fail doctor. Wait for a supporting Echo tag before changing the pin. GAP records only reported names and does not install or remove adapters.

### Publish destinations

- `~/.claude/rules/global-agent-policy.md`
- `~/.pi/agent/APPEND_SYSTEM.md`
- `~/.omp/agent/APPEND_SYSTEM.md`
- `$CODEX_HOME/gap/global-agent-policy.md` (`~/.codex` when unset)
- `~/.cursor/rules/global-agent-policy.mdc`
- `~/.empryo/EMPRYO.md`. The SoulStack block and any other text there stay outside the GAP markers.
- `$JCODE_HOME/prompt-overlay.md` (`~/.jcode` when unset; a relative or set but empty `JCODE_HOME` stops the sync, because jcode reads an empty one as its working folder). Text outside the GAP markers stays as written.
- `~/.omp/agent/commands/<name>.md` for each `global/commands/*.md`
- `~/.claude/commands/<name>.md` for the same file. Claude Code loads that path as a user slash command. The prompt uses Claude's `$ARGUMENTS` and `argument-hint`, so the file is copied unchanged.
- `~/.pi/agent/prompts/<name>.md` for the same file. Pi loads that directory as prompt templates and expands `$ARGUMENTS` (proved 2026-11-12 with a probe template under Pi 1.5.2).

Do not add a destination nothing reads. Grok loads the Claude file when Claude compatibility is on. Confirm with `grok inspect` before adding a Grok destination. A second copy loads the policy twice.
