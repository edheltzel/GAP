# AGENTS.md

## Purpose

`gap` publishes this checkout's `global/AGENTS.md` and each `global/commands/*.md`, installs the skills listed in `global/skills.json`, and installs each component pinned in `gap.toml` from `gap.lock`.

## Ownership

- `cmd/gap/` owns publish, install, source-identity migration, and drift.
- Policy text stays in `global/`. Command prompts stay in `global/commands/`. Skill source stays in component repos. A manifest `"."` source would read `skills/` in this checkout, which the merge gate covers. The manifest stays in `global/skills.json`. Component pins stay in `gap.toml` and `gap.lock`.

## Local Contracts

`gap` publishes the checkout it was built from. `sourceRoot` is that compile-time path, so `gap sync` uses it from any directory. Curl installation retains a new checkout under `~/.gap/checkouts/` each time. `sh scripts/install.sh` builds the local checkout regardless of stdin. Both run `go install ./cmd/gap`, check that the shell can find the binary, and require keeping the source checkout. Reinstall after `cmd/gap` changes, after the checkout moves, or after a `-trimpath` build. `go run ./cmd/gap sync` from the repo root uses that checkout without installing.

`gap sync` publishes unless the effective profile is `crew`; see [project setup](../../README.md#project-setup). `gap sync --remove-codex-legacy` is valid only for machine publication. Component status and its failure conditions are described in [components](../../README.md#components). `gap restore [id]` reinstalls selected drifted component skills from the lock. `gap pin <id>@<ref>` is the only command that writes `gap.lock`. `gap -h`, `gap --help`, and `gap help` print styled usage and exit 0. Invoking `gap` without a subcommand prints help and exits 2. An unknown command or extra arguments exit 1. A skipped destination or a failed skills step exits 1. Drift kept with both destinations complete exits 0. Skip, an incomplete keep, or drift with no terminal exits 1.

The setup breadcrumb contract, including the crew exception, is in [project setup](../../README.md#project-setup). The Echo adapter ledger contract and unsupported-report behavior are in [components](../../README.md#components).

### Sync steps

1. Resolve `$HOME` and `CODEX_HOME`. Empty `CODEX_HOME` means unset. A relative `CODEX_HOME` is refused.
2. Merge gate. Refuse unless HEAD is the primary branch (`origin/HEAD`, `master` here) or `gitbutler/workspace`. Refuse a worktree (`git-dir` differs from `git-common-dir`). Refuse when `global/`, `skills/`, `gap.toml`, or `gap.lock` differs from `origin/HEAD`, including untracked copies of those files. An ignored file blocks only if skills.sh would install it (a path under `skills/`) or gap reads it (`global/AGENTS.md`, `global/skills.json`, top-level `global/commands/*.md`, `gap.toml`, `gap.lock`). `.DS_Store` and `node_modules` do not block. Unset `origin/HEAD` is a refuse.
3. Publish `global/AGENTS.md`. Rewrite `](docs/agents/` links to the absolute `global/docs/agents/` path in this checkout. The payload sits between `<!-- gap:begin -->` and `<!-- gap:end -->`. The Cursor file gets an `alwaysApply: true` frontmatter wrap before those markers only when GAP creates it or migrates an older whole-file publish. Write regular files only. A symlink is foreign. Then publish each top-level `global/commands/*.md` unchanged, as a whole file, to `~/.omp/agent/commands/<name>.md` and `~/.claude/commands/<name>.md`. Commands are not spliced. A missing `global/commands/` publishes nothing.
4. Ledger each written destination in `~/.gap/published.json`. A policy entry is the sha256 of the block between the markers, not the whole file. A missing policy file is written as markers plus payload. A file with complete GAP marker pairs on standalone lines is updated by replacing only the last pair and its contents. Everything outside that pair stays byte for byte. When the on-disk file already equals the publish, the destination is left in place and no recovery copy is made. Otherwise the previous file or symlink is moved under `~/.gap/recovery/<dest-id>/<timestamp>/` before the new file is installed (`<dest-id>` is the destination path relative to `$HOME`). If that rename cannot cross filesystems, the previous file is copied with its mode, fsync'd, verified, then the live destination is re-checked and only then removed. A destination that changes or disappears during that copy is refused, not aborted. Older copies for that destination are then pruned, keeping the 3 newest regular files. A displaced user symlink is never pruned. A moved leftover `.<filename>.gap-recovery-*` folder is never pruned. A prune failure prints a warning and does not fail the sync. Recovery stays out of harness rule directories. Leftover `.<filename>.gap-recovery-*` directories next to a managed destination, left by an earlier build, are moved into `~/.gap/recovery/<dest-id>/` and the new path is printed. A failed move prints a warning and leaves the folder in place. A concurrent edit that lands only in the recovery copy prints a warning with that path; a retained previous file prints its recovery path. A refused concurrent change names the recovery path, and a failed restore is included in that refusal. A file whose whole contents match the ledger digest, or equal the current unmarked payload, is an older whole-file publish. It is rewritten as markers plus the current payload. Anything else is foreign. A terminal asks once to append the GAP block. Yes copies the file to `~/.gap/backups/` and appends the block. The rest stays, so the harness keeps loading it. No, or no terminal, leaves that file alone. Other destinations still publish. A symlink cannot be spliced. Yes moves it into `~/.gap/recovery/` and writes a regular file. If that replace stops before the move, the empty recovery folder is removed. That harness stops loading the old target. The recovery copy keeps the bytes only. A command entry is the sha256 of the whole file. A foreign command file is replaced after a yes. The backup keeps the bytes only.
5. If this run wrote the Codex policy file, add SessionStart and SubagentStart hooks that `cat` it. The file counts as this publish when its GAP block equals the payload. `--remove-codex-legacy` runs before that hook install. It strips an old policy prefix from `CODEX_HOME/AGENTS.md` only when this run published the policy file and both hooks were already in `hooks.json`. The cleaned ledger value is `cleaned`, not a digest.
6. Read `global/skills.json`; the effective `gap.toml` and `gap.lock` were resolved before publication. A missing `gap.toml` is an empty distro. Schema must be `"2"`. Every selected component needs a lock entry or sync stops before publication and names `gap pin <id>@<ref>`. Sync never moves pins. Each pin is fetched into `~/.gap/store/<id>/<commit>` (reused, with no network, when its on-disk source tree matches the lock). The store keeps git's file modes, so installed copies stay writable and executable bits survive. It is trusted only after its worktree tree id matches the lock, checked on every use with a temporary Git index and object directory. Seed that index from `HEAD`, then stage changes without forcing ignored files. This ignores untracked build output while still detecting tracked edits, deletions, and mode changes. The store's real index and objects stay untouched. `.git` stays so the tree can be checked again. A component skill's baseline is that store path, independent of the skills.sh lock. A mismatched tree is an error and is not installed. Manifest source `"."` is this checkout. Any other manifest source is `owner/repo`, optionally with a subpath. A component repo is `github.com/owner/repo` (clone URL `https://github.com/owner/repo.git`), a `file://` URL, or an absolute path.
7. Install selected skills as defined in [Manage skills](../../README.md#manage-skills), including load levels, destinations, component-owned installers, and runtime requirements. Both skill destinations must exist and match the source hash. That hash skips `node_modules`, `.git`, `__pycache__`, `__pypackages__`, and `metadata.json` on both the source and the installed copy. Skills selected by neither the manifest nor a component are never touched.
8. Manifest source-identity migration. The skills.sh lock file is `$XDG_STATE_HOME/skills/.skill-lock.json` when `XDG_STATE_HOME` is set, otherwise `~/.agents/.skill-lock.json`. An entry whose source is not the manifest source is foreign. `"."` matches the absolute checkout path. `owner/repo`, a github.com URL, and a subpath are one identity. A missing or unreadable lock file is not a mismatch. Automatic migration runs only when both copies match the recorded hash (40-hex git tree or 64-hex skills.sh SHA-256). It backs up both destinations under `~/.gap/backups/` and reinstalls from the manifest. A failed migration restores those destinations and the previous lock entry. A missing or unverifiable hash, or an edited copy, goes to drift review and is not replaced without a choice. Component entries bypass this legacy-lock migration; see [Manage skills](../../README.md#manage-skills).
9. Drift check. Compare each managed skill with its source: the pinned store for a component, this checkout for source `"."`, or the skills.sh lock hash for another manifest source. On drift, a terminal shows the diff and asks `[k]eep installed`, `[t]ake source`, or `[s]kip`. An edited external skill clones the manifest source for that diff, not the lock's old source. Keep with both destinations complete leaves the copies and exits 0. An incomplete keep still exits 1. Take source backs up both destinations, reinstalls, and on failure restores those destinations and the previous lock entry. Skip exits 1. No terminal: the skill is left in place, the drift is listed, and the run exits 1. After drift resolution, including failed repairs, each `~/.empryo/skills/<name>` whose content hash differs from the resulting `~/.agents/skills/<name>` prints one warning; Empryo loads that copy first. The name `empryo` is Empryo's own and is skipped. gap never writes or deletes there, and the warning does not change the exit code.
10. Empryo pins. When `~/.empryo/config.json` exists and its `skills.autoLoad` differs from `empryoPins` (`do-todo`, `do-commit`, `but-axi`), print the `settings` call that sets it. gap only reads that file. Empryo's `settings` tool cannot write `presets`, and a global `skills.autoLoad` beats any preset, so GAP ships no preset.

### Publish destinations

- `~/.claude/rules/global-agent-policy.md`
- `~/.pi/agent/APPEND_SYSTEM.md`
- `~/.omp/agent/APPEND_SYSTEM.md`
- `$CODEX_HOME/gap/global-agent-policy.md` (`~/.codex` when unset)
- `~/.cursor/rules/global-agent-policy.mdc`
- `~/.empryo/EMPRYO.md`. The SoulStack block and any other text there stay outside the GAP markers.
- `~/.omp/agent/commands/<name>.md` for each `global/commands/*.md`
- `~/.claude/commands/<name>.md` for the same file. Claude Code loads that path as a user slash command. The prompt uses Claude's `$ARGUMENTS` and `argument-hint`, so the file is copied unchanged.

Do not add a destination nothing reads. Grok loads the Claude file when Claude compatibility is on. Confirm with `grok inspect` before adding a Grok destination. A second copy loads the policy twice.
