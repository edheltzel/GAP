Final Recommendation

Adopt Path A (Backlog.md) as the state layer. Rationale:

  • Zero vendor lock-in — tasks live in git alongside code, MCP-accessible by every agent you use
  • Offline-capable — fits your distributed multi-agent reality (CC + OpenCode + Pi + Codex)
  • Cheapest reversibility — adopting Backlog.md doesn't preclude later Linear migration; Linear has a Backlog.md import path
  • Schema continuity — your existing .atlas/plans/ frontmatter (phase, percent_complete, next_action) maps cleanly to Backlog.md task fields

Add a small Atlas-native atlas next command that aggregates across ~/Developer/*/. atlas/plans/*.md + backlog/* per project, returning a single ranked answer. This is the "what's next" function the data shows is missing from every off-the-shelf tool.

Do NOT migrate GitHub issues yet. Keep GitHub for external/public-facing work (PRs, public bug reports, OSS contributions). Backlog.md handles your private per-project task state — the layer that's currently rotting.
