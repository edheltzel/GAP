Phase 4 — Architecture Decisions (Design First)

Algorithm Adoption: Baseline-First, Not Forward-Port

Red Team verdict (AR-2 + IN-8 convergent): The 86KB Algorithm is sediment from 80+ iteration files, not principled design. v3.5.0 replaced Constraint Fidelity with structural mechanisms (ISC Splitting Test + mandatory capability invocation). Forward-porting creates contradictory quality gates.

Revised strategy:

  • Step 1: Read v3.5.0 Algorithm in full. Map every v1.2.0 addition to its v3.5.0 structural equivalent.
  • Step 2: For each v1.2.0 addition where v3.5.0 has a structural replacement (e.g., Constraint Fidelity → ISC Splitting Test), adopt v3.5.0's approach. Do NOT forward-port.
  • Step 3: For each v1.2.0 addition where v3.5.0 has NO equivalent (if any), evaluate independently whether it's worth adding to v3.5.0.
  • Step 4: Update Components/Algorithm/ with a new version file (v3.5.0-atlas.md). Run RebuildPAI.ts.
