Track

Track authored, portable files only:

  • config.yml — global OMP settings.
  • models.yml — custom model/provider definitions. Use environment-variable names for keys, never literal tokens.
  • mcp.json — OMP-owned MCP server config and discovered-server overrides. Use disabledServers to suppress foreign MCP entries that OMP must not launch; prefer ${ENV} placeholders or env-name indirection for configured servers.
  • keybindings.yml — user key remaps.
  • APPEND_SYSTEM.md — preferred global prompt additions; keeps OMP defaults, generated skills/rules/tool guidance, and project context.
  • SYSTEM.md — rare; replaces OMP's stable default instruction block, so do not add unless that is intentional.
  • skills/*/SKILL.md — one skill directory per skill, with explicit name and description frontmatter.
  • commands/*.md, rules/*.{md,mdc}, prompts/*.md, instructions/*.md.
  • tools/*.ts, tools/<name>/index.ts — authored custom tools.
  • extensions/*.ts, extensions/<name>/index.ts — authored extensions. Do not track files marked as installed or managed by another app.
  • themes/*.json — custom OMP themes.

Adding OMP files

  1. Put stowed global config under omp/.omp/agent/.
  2. Put installable local OMP extension packages under packages/<name>/ with package.json#omp.extensions.
  3. Put local marketplace entries in .claude-plugin/marketplace.json.
  4. Put external OMP marketplace packages in omp-plugins.txt as owner/repo=plugin@marketplace.
  5. If the matching live stowed file already exists under ~/.omp/agent/, use stow --adopt once or move the file into the repo before restowing.
  6. Run just up after changing stowed global config. Run just omp-plugins-status and just omp-plugins-install after changing the plugin manifest.
  7. If stow reports a conflict, resolve the live file deliberately; do not delete runtime state directories to make stow pass.

OMP marketplace plugins

omp-plugins.txt is the tracked desired state for user-scoped OMP marketplace packages. install-omp-plugins.sh adds or updates each declared marketplace, then installs or upgrades its plugin. OMP owns the live registry and downloaded cache under ~/.omp/plugins/; those runtime files remain untracked.

Compound Engineering is declared as EveryInc/compound-engineering-plugin=compound-engineering@compound-engineering-plugin. OMP therefore loads CE from its own marketplace cache instead of relying on the lower-priority Claude-plugin discovery copy. Keep the Claude plugin installed for Claude Code. Do not port CE's Pi resources_discover extension into OMP: marketplace skill discovery already owns the root skills/ directory, while OMP 17 does not invoke that Pi discovery event from AgentSession.

  • just omp-plugins-status prints the add/update and install/upgrade operations without applying them.
  • just omp-plugins-install applies the manifest.
  • just omp, just link, and just up also provision the OMP plugin manifest.
  • The installer validates the complete manifest before invoking OMP, treats only a user-scoped entry as installed, and refuses to update a marketplace whose registered source differs from the manifest. For an intentional source migration, run omp plugin marketplace remove <name>, then rerun provisioning.
  • Focused installer contracts live at tests/omp/install-omp-plugins.test.ts.
  • Verify ownership with omp plugin list; CE must appear under Marketplace Plugins.

Prompt template execution profiles

packages/omp-prompt-template-model/ adds execution frontmatter to OMP prompt templates without loading Pi's extension runtime. The stowed omp/.omp/agent/extensions/omp-prompt-template-model link exposes the package, and omp/.omp/agent/config.yml loads its entrypoint explicitly.

---
description: Review with a contrasting model
model: ["@slow", "openai-codex/gpt-5.6-sol"]
thinking: xhigh
skill: ce-code-review
restore: true
subagent: reviewer
inheritContext: false
---
Review $1 against $ARGUMENTS.
  • model accepts one selector, a comma-separated fallback list, or a YAML array; OMP tries selectors in order and uses the first model it can resolve and activate.
  • thinking accepts OMP's off, minimal, low, medium, high, xhigh, and max levels.
  • skill injects the named OMP skill for the command's next turn.
  • subagent adds native task delegation guidance. true uses the configured default agent; a string names the agent. inheritContext defaults to false.
  • restore defaults to true and restores the prior model and thinking level after the delegated turn ends.
  • $1, $2, $@, $ARGUMENTS, $@[start:length], $@[start:], ${@:start}, ${@:start:length}, {{arguments}}, {{ARGUMENTS}}, and {{arg N}} use OMP-compatible, non-recursive argument substitution.
  • Profile commands never shadow OMP built-ins, discovered file commands, or unrelated extension, custom, and skill commands; the existing command remains authoritative and OMP logs the collision.

Execution-profile templates in <cwd>/.omp/prompts/ override matching user templates in OMP's profile-aware agent prompt directory (normally ~/.omp/agent/prompts/). Files without execution frontmatter remain owned by OMP's native prompt loader.

Atlas status line

omp/.omp/agent/extensions/atlas-status-line.ts owns the canonical Atlas footer. omp/.omp/agent/config.yml lists it explicitly because native discovery does not traverse the stowed extension-directory symlink. Run just up when adding an authored OMP file and just omp for later package-only restows; focused tests live at tests/omp/atlas-status-line.test.ts.

The authored fields use OMP's native status-line shape: π {OMP_VERSION}  {provider}/{model}  {thinking}  …/{parent}/{current}   {branch}  {context meter} {context}%   {cache}%, followed by the native horizontal divider and a right-aligned session title when one exists.

  • Show cache only after cumulative session usage reports real cache read/write activity.
  • Keep status glyphs single-cell under OMP's visibleWidth: the thinking indicator uses the Nerd Font nf-fa-bolt glyph instead of the U+26A1/U+FE0E emoji sequence, which Ghostty paints one cell narrower than OMP measures and therefore detaches the editor's right corner.
  • Register a below-editor widget as the extension's TUI lifecycle anchor, then install the Atlas primary row through the editor's setTopBorderProvider. Match OMP's default top-border composition: grouped content uses thin powerline separators, the divider fills the gap before the session title, and the editor supplies any remaining trailing rule and right corner. Restore OMP's native getTopBorder provider and leave borderColor untouched when the widget is disposed or the editor changes. Keep native status-line segments empty through the custom preset.
  • Keep one primary row with native group insets. At narrow widths, drop path, branch, model metadata, then OMP version; preserve the responsive context meter and cache, and ANSI-truncate the session title into the right group when space remains.
  • Read provider, model, thinking, OMP version, compaction-aware context, session title, and cumulative cache usage from live state. Never read or render removed LifeOS version state. Re-read the session working directory and active branch during rendering so /move updates the existing footer without a restart.
  • Capture ui.setStatus publications through the widget as inset rows beneath the editor. Preserve only trusted ANSI SGR styling, strip other controls, terminate every published status with a full SGR reset, and reapply the opaque row background so styles cannot bleed between publishers or beyond the row. Restore OMP's publisher on session switch or shutdown and use ANSI-aware measurement and truncation.
  • Derive footer text, separators, semantic percentages, icons, path, branch, divider, and background from the active OMP theme. omp/.omp/agent/themes/atlas-default.json remains an intentional snapshot of OMP 17.0.1's built-in dark theme with only its name changed; config.yml selects atlas-eldritch as theme.dark. Other active themes require no footer-specific palette.
  • Use the theme's statusLineBg behind the primary groups and full-width auxiliary status rows, or inherit the terminal background when statusLine.transparent: true. Only the context bar keeps the canonical Atlas dark or Rosé Pine Dawn gradient and dim empty ⛁ cells, with widths of 6 (<35 columns), 8 (35–54), 16 (55–79), or 24 (80+). The percentage follows the active theme.
  • Published OMP 17 still types ctx.ui.setFooter but leaves it inert in interactive mode. Do not call it or restore downstream core wiring; the extension-only bridge uses the widget factory's TUI handle, public component children, native getTopBorder, and the editor's public setTopBorderProvider and borderColor surfaces.

OMP updates

The published package installed by OMP's official updater is canonical. OMP 17 incorporated the streamed-response fixes that previously required local patches; the Atlas footer uses the release's supported widget API instead of patching OMP core.

  • Run omp update to install the latest published release.
  • Run omp update --check for a non-installing availability check.
  • Run just omp after changing authored files under omp/.omp/agent/; stow manages configuration, not the OMP binary.
  • Never relink ~/.bun/bin/omp to a local source wrapper, revive a retired patch branch, or pin an older release.
