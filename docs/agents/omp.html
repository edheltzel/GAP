Track

Track authored, portable files only:

  • config.yml — global OMP settings.
  • models.yml — custom model/provider definitions. Use environment-variable names for keys, never literal tokens.
  • mcp.json — OMP-owned MCP server config and discovered-server overrides. Use disabledServers to suppress foreign MCP entries that OMP must not launch; prefer ${ENV} placeholders or env-name indirection for configured servers.
  • keybindings.yml — user key remaps.
  • APPEND_SYSTEM.md — preferred global prompt additions; keeps OMP defaults, generated skills/rules/tool guidance, and project context.
  • SYSTEM.md — rare; replaces OMP's stable default instruction block, so do not add unless that is intentional.
  • skills/*/SKILL.md — one skill directory per skill, with explicit name and description frontmatter.
  • commands/*.md, rules/*.{md,mdc}, prompts/*.md, instructions/*.md.
  • tools/*.ts, tools/<name>/index.ts — authored custom tools.
  • extensions/*.ts, extensions/<name>/index.ts — authored extensions. Do not track files marked as installed or managed by another app.
  • themes/*.json — custom OMP themes.

Adding OMP files

  1. Put stowed global config under omp/.omp/agent/.
  2. Put installable OMP extension packages under packages/<name>/ with package.json#omp.extensions.
  3. Put marketplace entries in .claude-plugin/marketplace.json.
  4. If the matching live stowed file already exists under ~/.omp/agent/, use stow --adopt once or move the file into the repo before restowing.
  5. Run just up after changing stowed global config. Package-only changes do not need stow.
  6. If stow reports a conflict, resolve the live file deliberately; do not delete runtime state directories to make stow pass.

Atlas status line

omp/.omp/agent/extensions/atlas-status-line.ts owns the canonical Atlas footer. omp/.omp/agent/config.yml lists it explicitly because native discovery does not traverse the stowed extension-directory symlink. Install both with just omp; focused tests live at tests/omp/atlas-status-line.test.ts.

▲ Atlas v{LIFEOS_VERSION} · {provider}/{model} ⚡︎ {thinking} · π {OMP_VERSION} · …/{parent}/{current} ·  {branch} on the left; {context meter} {context}% ·  {cache}% on the right.

  • Show cache only after a successful assistant request reports real cache read/write usage, and omit it below 80 columns.
  • Register through OMP 17's supported ctx.ui.setWidget(..., { placement: "belowEditor" }) surface so the footer sits beneath the editor divider. Leave native status-line segments empty through the custom preset and retain showHookStatus as the native fallback.
  • Keep one full-width primary row with one leading and trailing space. At narrow widths, preserve the responsive context meter, drop path/OMP/branch metadata in that order, and ANSI-truncate the remaining model group instead of wrapping.
  • Read Atlas, provider, model, thinking, OMP version, branch, compaction-aware context, and latest successful cache usage from live state.
  • Capture ui.setStatus publications as inset additional rows. Preserve only trusted ANSI SGR styling, strip other controls, restore OMP's publisher on session switch or shutdown, and use ANSI-aware measurement and truncation.
  • Derive footer text, separators, semantic percentages, icons, path, branch, and background from the active OMP theme. omp/.omp/agent/themes/atlas-eldritch.json is the selected Atlas dark theme; other active themes require no footer-specific palette.
  • Fill opaque rows with the theme's statusLineBg, or inherit the terminal background when statusLine.transparent: true. Only the context bar keeps the canonical Eldritch or Rosé Pine Dawn gradient and dim empty ⛁ cells, with widths of 6 (<35 columns), 8 (35–54), 16 (55–79), or 24 (80+). The percentage follows the active theme.
  • Published OMP 17 still types ctx.ui.setFooter but leaves it inert in interactive mode. Do not call it and do not restore downstream footer wiring.

OMP updates

The published package installed by OMP's official updater is canonical. OMP 17 incorporated the streamed-response fixes that previously required local patches; the Atlas footer uses the release's supported widget API instead of patching OMP core.

  • Run omp update to install the latest published release.
  • Run omp update --check for a non-installing availability check.
  • Run just omp after changing authored files under omp/.omp/agent/; stow manages configuration, not the OMP binary.
  • Never relink ~/.bun/bin/omp to a local source wrapper, revive a retired patch branch, or pin an older release.
